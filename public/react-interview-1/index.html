01 基础概念
Q1
React 中虚拟 DOM 是什么？它解决了什么问题？
初级核心原理
▶
虚拟 DOM（Virtual DOM）是用 JavaScript 对象描述真实 DOM 树的一种抽象层。

解决的问题：
  • 真实 DOM 操作成本高，频繁操作会触发重排重绘
  • 虚拟 DOM 通过 Diff 算法，仅将变化部分同步到真实 DOM（最小化更新）
  • 提供了跨平台抽象能力（React Native、SSR）
工作流程： state/props 变化 → 生成新 vDOM → Diff 对比旧 vDOM → patch 到真实 DOM
Q2
受控组件与非受控组件的区别？
初级表单
▶
受控组件：表单数据由 React state 控制，每次变化都触发 onChange 并同步 state。数据流单向且可预测。

非受控组件：表单数据由 DOM 自身维护，通过 ref 直接读取 DOM 值，无需 state 同步。

// 受控
const [val, setVal] = useState('')
<input value={val} onChange={e => setVal(e.target.value)} />

// 非受控
const ref = useRef()
<input ref={ref} defaultValue="初始值" />
推荐优先使用受控组件，便于验证、格式化和联动。
Q3
React 中 key 的作用是什么？为什么不能用 index？
初级列表渲染
▶
key 帮助 React 在 Diff 时识别哪些元素发生了变化、被添加或删除，从而复用已有的 DOM 节点，提升性能。

用 index 的问题：当列表顺序变化（排序、删除头部元素）时，index 与元素的对应关系改变，导致 React 错误地复用旧 DOM，引发状态混乱（如输入框内容错位）。

正确做法：用数据唯一 ID 作为 key，如 key={item.id}
Q4
什么是 JSX？它如何被转换为 JavaScript？
初级语法
▶
JSX 是 JavaScript 的语法扩展，允许在 JS 中写类 HTML 标记。Babel 会将 JSX 转译为 React.createElement() 调用（React 17+ 使用新 JSX Transform，自动导入 react/jsx-runtime）。

<Button color="blue">Click</Button>
// 转译为：
React.createElement(Button, { color: 'blue' }, 'Click')
02 Hooks 深度
Q5
useEffect 的依赖数组三种形态的区别？
中级Hooks
▶ 
// 1. 无依赖数组 → 每次渲染后都执行
useEffect(() => { ... })

// 2. 空数组 → 仅挂载时执行一次（相当于 componentDidMount）
useEffect(() => { ... }, [])

// 3. 有依赖 → 依赖项变化时才执行
useEffect(() => { ... }, [count, id])
清理函数：返回的函数在下次 effect 执行前或组件卸载时调用，用于清除订阅、定时器等副作用。
Q6
useMemo 与 useCallback 的区别与使用场景？
中级性能优化
▶
useMemo：缓存计算结果（值），避免每次渲染都重复昂贵计算。
useCallback：缓存函数引用，避免子组件因父组件重渲染导致接收到新函数引用而不必要地重渲染。

const sorted = useMemo(() => data.sort(...), [data])
const handleClick = useCallback(() => { ... }, [id])
使用原则：不要滥用，仅在有性能问题时使用。过度使用会增加内存开销和代码复杂度。配合 React.memo 才能发挥最大效果。
Q7
useRef 除了访问 DOM，还有哪些用途？
中级Hooks
▶
useRef 返回一个在整个组件生命周期内持久存在的可变对象（.current），修改它不会触发重渲染。

常见用途：
  • 保存定时器 ID（clearInterval(timerRef.current)）
  • 保存上一次的 props/state 值
  • 存储不影响渲染的实例变量（如 WebSocket 实例）
  • 在闭包中获取最新值（避免 stale closure）
Q8
解释 Hooks 的闭包陷阱（stale closure）及解决方案
高级Hooks · 陷阱
▶
问题：useEffect/useCallback 等 Hook 内的函数捕获了创建时的变量快照，当依赖未正确声明时，读取的是过期的旧值。

// 陷阱：count 永远是 0
useEffect(() => {
  const id = setInterval(() => console.log(count), 1000)
  return () => clearInterval(id)
}, []) // 缺少 count 依赖
解决方案：
  • 正确声明所有依赖（使用 ESLint exhaustive-deps 规则）
  • 用 useRef 保存最新值：const countRef = useRef(count)
  • 使用函数式 setState 更新：setCount(c => c + 1)
Q9
如何实现一个自定义 Hook？有哪些设计原则？
高级自定义 Hooks
▶
自定义 Hook 是以 use 开头的函数，内部可以调用其他 Hooks，用于复用有状态逻辑（非 UI）。

function useFetch(url) {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(true)
  useEffect(() => {
    fetch(url).then(r => r.json()).then(d => {
      setData(d); setLoading(false)
    })
  }, [url])
  return { data, loading }
}
设计原则：
  • 只提取逻辑，不包含 JSX
  • 参数保持稳定引用（避免无限循环）
  • 返回值语义清晰，优先返回对象（方便按需解构）
  • 处理好清理逻辑，避免内存泄漏
03 性能优化
Q10
React.memo 的工作原理及适用场景？
中级性能
▶
React.memo 是高阶组件，对函数组件进行浅比较（shallow compare）：如果 props 没有变化，跳过渲染，直接复用上次结果。

const Child = React.memo(({ name }) => <div>{name}</div>)
// 也可自定义比较函数：
const Child = React.memo(Component, (prev, next) => {
  return prev.id === next.id // 返回 true 则跳过渲染
})
适用场景：纯展示组件、父组件频繁重渲染但子组件 props 基本不变时。
注意：若 props 包含对象/函数引用，需配合 useMemo/useCallback 保证引用稳定。
Q11
什么是代码分割？如何在 React 中实现？
中级性能 · 工程化
▶
代码分割将应用拆分为多个较小的 chunk，按需加载，减少初始 bundle 体积，提升首屏性能。

import { lazy, Suspense } from 'react'
const Chart = lazy(() => import('./Chart'))

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Chart />
    </Suspense>
  )
}
策略：按路由分割（每个页面单独 chunk）、按功能分割（弹窗、图表等重型组件）。结合 webpack/vite 的动态 import 实现。
Q12
解释 React 18 的并发特性（Concurrent Features）
高级React 18 · 并发
▶
React 18 引入并发模式，允许渲染工作被中断、暂停和恢复，优先响应用户交互。

核心 API：
  • useTransition：将非紧急更新标记为 transition，避免阻塞用户输入（如搜索过滤）
  • useDeferredValue：延迟某个值的更新，类似防抖但由 React 调度
  • startTransition：同 useTransition，命令式版本
  • Suspense + streaming SSR：服务端流式传输 HTML
const [isPending, startTransition] = useTransition()
startTransition(() => {
  setFilter(input) // 低优先级更新，不阻塞输入
})
04 状态管理
Q13
Context API 的使用与性能问题如何解决？
初级Context
▶
Context 解决 prop drilling 问题，但 Context value 变化会导致所有消费者重渲染。

优化策略：
  • 拆分 Context（将频繁变化的值与稳定的值分开）
  • 用 useMemo 包裹 value 对象，避免每次渲染都创建新引用
  • 消费者组件用 React.memo 包裹
  • 数据量大时考虑 Zustand/Jotai 等原子化状态库
Q14
Redux 的核心原则及与 Zustand 的对比？
中级状态管理
▶
Redux 三原则：单一数据源、State 只读（通过 action 修改）、纯函数 reducer。

Zustand 对比：
  • API 更简洁，无 action/reducer 样板代码
  • 天然支持细粒度订阅（selector），避免无关重渲染
  • 不依赖 Provider 包裹
  • 中小项目首选；Redux Toolkit 在大型团队协作和 devtools 方面更成熟
const useStore = create(set => ({
  count: 0,
  inc: () => set(s => ({ count: s.count + 1 }))
}))
Q15
useState 与 useReducer 如何选择？
中级状态管理
▶
useState 适合：简单独立的状态，如 toggle、输入值、计数器。

useReducer 适合：
  • 状态对象包含多个字段，且更新逻辑复杂
  • 下一个状态依赖多个当前状态字段
  • 需要集中管理状态转换逻辑（便于测试）
经验规则：当你发现在 useState 里写了超过 3 个相关 state 且频繁一起更新时，考虑 useReducer。
05 原理深度
Q16
React Fiber 架构解决了什么问题？
高级Fiber · 架构
▶
React 15 使用递归同步渲染，一旦开始无法中断，大型组件树更新会导致主线程长时间阻塞，页面卡顿掉帧。

Fiber 解决方案：
  • 将渲染工作拆分为可中断的小单元（Fiber 节点）
  • 基于优先级调度（Lane 模型），高优先级任务可打断低优先级任务
  • 两个阶段：Render 阶段（可中断）→ Commit 阶段（不可中断）
  • 双缓冲技术：current tree 和 workInProgress tree 交替使用
这是 Concurrent Mode 的基础设施。
Q17
React 的合成事件系统是什么？为什么这样设计？
高级事件系统
▶
React 将所有原生事件统一代理到根节点（React 17+ 是 root container，之前是 document），通过事件冒泡统一处理，并封装为跨浏览器一致的 SyntheticEvent。

设计优势：
  • 跨浏览器兼容性（磨平差异）
  • 事件池复用（React 16，减少 GC 压力）
  • 统一管理，便于实现并发模式下的优先级调度
  • React 17 后不再冒泡到 document，修复了与第三方库的兼容问题
Q18
解释 React 的 Diff 算法策略（三个假设）
高级Diff 算法
▶
标准树 Diff 复杂度 O(n³)，React 基于三个启发式假设将其降至 O(n)：

  • 假设1 - 层级比较：只对同层节点进行比较，跨层级移动直接删除重建（实际场景极少跨层移动）
  • 假设2 - 类型判断：不同类型的元素产生完全不同的树，直接销毁旧树重建新树
  • 假设3 - key 优化：列表元素提供 key 时，通过 key 识别同一元素的移动，而非删除重建
这三个假设在 99% 的实际 UI 场景中成立，是 React 高效更新的核心。
Q19
React 组件的生命周期（函数组件版）对应关系？
初级生命周期
▶ 
// 挂载 (componentDidMount)
useEffect(() => { ... }, [])

// 更新 (componentDidUpdate)
useEffect(() => { ... }, [dep])

// 卸载 (componentWillUnmount)
useEffect(() => {
  return () => { /* 清理 */ }
}, [])

// getDerivedStateFromProps
// → 渲染期间直接计算（无副作用）
const derived = useMemo(() => compute(props), [props.x])
函数组件没有 shouldComponentUpdate，用 React.memo 替代。
Q20
什么是 Error Boundary？函数组件如何实现？
初级错误处理
▶
Error Boundary 是捕获子组件渲染错误的机制，防止整个应用崩溃。目前只能用类组件实现（通过 componentDidCatch 和 getDerivedStateFromError）。

函数组件可使用第三方库 react-error-boundary：

import { ErrorBoundary } from 'react-error-boundary'

<ErrorBoundary fallback={<div>出错了</div>}>
  <RiskyComponent />
</ErrorBoundary>
注意：Error Boundary 不能捕获异步错误、事件处理器中的错误。
Q21
描述一次完整的 React 渲染流程
中级渲染原理
▶
触发（Trigger）→ 渲染（Render）→ 提交（Commit）

  • 触发：初始渲染 / setState / forceUpdate 触发调度
  • Render 阶段（可中断）：从根节点开始，调用函数组件（执行 Hooks）生成新 Fiber 树，与旧树 Diff，收集副作用列表
  • Commit 阶段（不可中断）：
    • BeforeMutation：执行 getSnapshotBeforeUpdate
    • Mutation：DOM 操作（插入/更新/删除）
    • Layout：执行 useLayoutEffect，更新 refs
  • 异步：浏览器绘制后，执行 useEffect
Q22
useLayoutEffect 与 useEffect 的区别？
中级Hooks · 渲染
▶
执行时机不同：
  • useLayoutEffect：DOM 更新后、浏览器绘制前同步执行（阻塞绘制）
  • useEffect：浏览器绘制后异步执行
适用场景：
  • 需要在用户看到更新前读取/修改 DOM 布局（如测量尺寸、避免闪烁），用 useLayoutEffect
  • 数据请求、订阅、日志等副作用，用 useEffect（避免阻塞渲染）
SSR 场景下 useLayoutEffect 会警告，需条件使用。
Q23
React Portals 是什么，典型应用场景？
中级Portal
▶
createPortal 允许将子组件渲染到父组件 DOM 层级之外的节点，但事件冒泡仍遵循 React 组件树（而非 DOM 树）。

import { createPortal } from 'react-dom'
return createPortal(<Modal />, document.body)
典型场景：Modal 弹窗（避免 overflow:hidden 裁剪）、Tooltip（避免 z-index 层叠问题）、全屏 Drawer。
Q24
如何排查和解决 React 应用的性能瓶颈？
高级性能 · 工程
▶
排查工具：
  • React DevTools Profiler：录制渲染，查看哪些组件重渲染及耗时
  • Chrome Performance 面板：查看长任务、Layout 抖动
  • why-did-you-render 库：自动检测不必要的重渲染
常见优化手段：
  • React.memo + useCallback/useMemo 减少子组件重渲染
  • 虚拟列表（react-window）处理大量列表项
  • 懒加载 + Suspense 减小初始包体积
  • 状态下移（将 state 放到真正需要它的组件）
  • 批量更新（React 18 自动批处理）
  • 避免在渲染函数中创建新对象/函数
Q25
React Server Components (RSC) 与客户端组件的区别？
高级React 19 · SSR
▶
服务端组件（RSC）：
  • 在服务器上渲染，不发送 JS 到客户端，零 bundle 体积
  • 可直接访问数据库、文件系统、私密 API
  • 不能使用 Hooks、事件处理、浏览器 API
  • 适合：数据获取、静态内容、重型第三方库
客户端组件（'use client'）：
  • 在浏览器执行，支持所有 Hooks 和交互
  • 需要交互、状态、浏览器 API 时使用
RSC 是 Next.js 13+ App Router 的核心，可将客户端 JS 体积大幅减少。
