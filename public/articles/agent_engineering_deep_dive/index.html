1. Agent 的本质

文章中把 Agent 的核心归纳为三块：怎么规划、怎么用工具、怎么记东西。这可以进一步扩展为：

Planning

把用户目标拆成可执行步骤，决定先做什么、后做什么。

Tool Use

通过函数调用、API、数据库、搜索、文件系统等工具与外部世界交互。

Memory

管理短期上下文和长期经验，避免每轮都从零开始。

与普通 ChatBot 不同，Agent 不是只回答问题，而是能围绕目标循环执行：观察、思考、行动、验证、继续行动。

2. Agent 核心循环：ReAct

ReAct = Reason + Act。工程上通常是一个循环：

1. 输入目标User Goal
2. 模型思考Reason
3. 选择工具Act
4. 接收结果Observation
5. 判断结束Final / Continue
for step := 0; step < maxSteps; step++ {
    response := llm.Call(messages, tools)

    if response.FinalAnswer != "" {
        return response.FinalAnswer
    }

    toolCall := response.ToolCall
    result, err := toolExecutor.Execute(ctx, toolCall)

    messages = append(messages, ToolResultMessage(result, err))
}
关键限制：生产环境必须设置 maxSteps、超时时间、工具白名单和审计日志，否则 Agent 可能陷入无限循环或执行危险操作。

3. 工具调用：Tool Definition 与 JSON Schema

文章提到“怎么把 Go 函数转成 OpenAI 能看懂的 JSON Schema”。这是 Agent 工程的核心。

3.1 工具定义应该包含什么

字段说明示例
name工具名称，必须稳定、清晰query_order_status
description什么时候使用这个工具根据订单号查询订单状态
parametersJSON Schema 参数定义order_id: string
permission工具权限read_only / write / admin
timeout最大执行时间3s / 10s

3.2 Go 中的工具声明示意

type QueryOrderArgs struct {
    OrderID string `json:"order_id" jsonschema:"required,description=订单号"`
}

func QueryOrderStatus(ctx context.Context, args QueryOrderArgs) (OrderStatus, error) {
    // 调用业务系统
    return orderClient.GetStatus(ctx, args.OrderID)
}

3.3 容错机制

  • JSON 解析失败：把错误返回给模型，让它重试。
  • 参数校验失败：明确指出哪个字段错误。
  • 工具超时：返回 timeout observation。
  • 业务错误：区分“可重试错误”和“不可重试错误”。
  • 危险操作：要求人工确认，例如删除、转账、发消息。

4. 记忆管理：短期记忆与长期记忆

类型存储内容实现方式风险
短期记忆当前对话上下文messages 数组、滑动窗口上下文过长、成本增加
摘要记忆长期对话摘要定期 summarization摘要损失细节
向量记忆历史事实、偏好、知识片段embedding + vector db召回错误记忆
结构化记忆用户画像、任务状态数据库字段隐私和权限问题
建议：能结构化的长期信息尽量结构化存储，不要所有内容都丢进向量库。

5. 任务规划：从简单 Agent 到复杂 Agent

5.1 单步工具 Agent

适合：查天气、查订单、查数据库。

用户问题 → 模型判断工具 → 调用工具 → 生成答案

5.2 多步 ReAct Agent

适合：需要连续检索、计算、判断的问题。

用户目标 → 规划第 1 步 → 调工具 → 观察结果 → 规划第 2 步 → ...

5.3 Plan-and-Execute

先生成完整计划，再按步骤执行。优点是整体性更好，缺点是计划可能过早固定。

5.4 Multi-Agent

多个 Agent 分工协作，例如：

  • Planner Agent：制定计划
  • Research Agent：检索资料
  • Coder Agent：写代码
  • Reviewer Agent：检查结果

6. Agent 安全与边界

风险说明治理方式
Prompt Injection外部文档诱导模型忽略系统规则隔离不可信内容，工具权限最小化
工具滥用模型调用不该调用的工具工具白名单、权限分级

7. Go 在 Agent 工程中的优势

文章强调 Go 在高并发、强类型、企业级编排上的优势。可以进一步拆解为：

并发与流式

Goroutine 适合处理大量长连接；Channel 可以连接 LLM 流式输出与 HTTP SSE/WebSocket。

Context 取消

用户断开连接时取消下游 LLM、数据库、RPC 请求，减少资源浪费。

强类型工具

用 struct 和 tag 生成 JSON Schema，降低参数错误。

工程稳定性

适合做 Agent Gateway、Tool Server、Workflow Engine。

7.1 推荐系统分层

API Layer
  - SSE / WebSocket / HTTP

Agent Orchestrator
  - Loop / Planning / Memory / Tool Routing

Tool Runtime
  - 参数校验 / 超时 / 重试 / 权限

Business Connectors
  - DB / RPC / Search / RAG / File / Message

Observability
  - Trace / Log / Eval / Audit

8. 面试高频问题与回答要点

Q1：Agent 和普通 ChatBot 有什么区别？

ChatBot 主要生成自然语言回答；Agent 可以根据目标调用工具、观察结果、多轮规划并执行任务。Agent 的核心是循环控制、工具使用、记忆管理和安全边界。

Q2：模型生成的工具参数错了怎么办？

先做 JSON Schema 校验；失败后把错误作为 observation 返回给模型，让模型自我修正；同时设置重试次数，超过次数后返回失败，不能无限重试。

Q3：如何防止 Agent 无限循环？

设置 maxSteps、全局 timeout、相同工具连续调用限制、状态机约束，以及必要时人工介入。

Q4：长期记忆应该怎么做？

对话摘要适合压缩历史上下文；向量记忆适合语义召回；用户偏好、任务状态等稳定信息更适合结构化数据库。长期记忆必须考虑隐私、删除和权限。
