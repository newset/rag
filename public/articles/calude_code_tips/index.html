01

@ 文件引用

最基础也最常用的技巧。在 CLAUDE.md 中使用 @路径 语法引用其他文件，Claude Code 读取时会自动展开内容，合并进上下文。适合拆分长文档，或复用已有的 README、架构文档，避免在 CLAUDE.md 里重复维护。

# CLAUDE.md

See @README.md for project overview
See @package.json for available npm commands

# 引用具体文档
- Git workflow: @docs/git-instructions.md
- Personal overrides: @~/.claude/my-project-instructions.md
适用场景：项目 README 已经写得很好，直接引用即可，不需要在 CLAUDE.md 里重复。架构决策文档、API 约定也同理。
02

多级目录 CLAUDE.md

CLAUDE.md 不只能放在项目根目录。Claude Code 支持在多个位置放置，按需自动合并加载，各层级互不冲突。

~/.claude/CLAUDE.md # 全局，对所有项目生效 ./CLAUDE.md # 项目根目录，提交 git 供团队共享 ./CLAUDE.local.md # 个人覆盖，加入 .gitignore ./src/CLAUDE.md # 操作 src/ 下文件时自动加载 ./prompts/CLAUDE.md # 只在处理该目录时加载

子目录的 CLAUDE.md 只在 Claude 实际操作该目录内文件时才被读取，不会污染其他任务的上下文窗口。对大型 monorepo 项目尤其有价值。

注意：CLAUDE.local.md 用于个人偏好（如本地路径、个人编码风格），不应提交 git，记得加入 .gitignore。
03

AGENTS.md 跨工具兼容 进阶

如果团队同时使用 Claude Code、GitHub Copilot、Codex 等多个 AI 编程工具，可以将规范内容统一放在 AGENTS.md，CLAUDE.md 只做一行引用：

# CLAUDE.md
@AGENTS.md

AGENTS.md 是社区新兴标准，Copilot 和 Codex 也能识别。这样真正的项目规范只需维护一份，各工具各自读取自己认识的文件名，互不干扰。

04

Skills 文件 按需加载

CLAUDE.md 每次 session 都会全量加载，文件过长会稀释指令效果。对于「有时需要但不是每次都用」的领域知识，应该放进 Skills 文件，让 Claude 按需加载，保持主上下文精简。

.claude/ └── skills/ ├── ctp-protocol/ │ └── SKILL.md # CTP/ctpbee 协议知识 ├── futures-trading/ │ └── SKILL.md # 期货合约规格、交易所规则 └── tradingview/ └── SKILL.md # Charting Library API 约定
CLAUDE.md 适合放

编码规范、架构概览、常用命令——每次都需要的核心上下文

Skills 适合放

特定领域知识、复用工作流——只在相关任务时才需要的内容

05

Hooks 确定性执行 100% 生效

CLAUDE.md 是「建议」，Claude 遵守率约 80%。Hooks 是「命令」，100% 执行。对于必须每次都发生的动作——格式化、lint、安全检查——应该做成 Hook 而不是写进 CLAUDE.md。

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "command": "ruff format ${file}" }]
    }],
    "PreToolUse": [{
      "matcher": "Bash",
      "command": "echo '[Hook] bash about to run'"
    }],
    "Stop": [{
      "command": "notify-send 'Claude finished'"
    }]
  }
}
技巧：让 Claude 帮你写 Hook——直接说「写一个每次编辑 Python 文件后自动运行 ruff 的 Hook」，Claude 会生成对应的 settings.json 配置。
06

强调关键指令

CLAUDE.md 文件越长，单条规则被遵守的概率越低。两个对策：一是保持文件在 200 行以内；二是对高优先级规则加强调词提升遵守率。

# 关键约束

IMPORTANT: 所有期货合约乘数必须从 CONTRACT_MULTIPLIERS 读取，禁止硬编码

YOU MUST: 修改 ctpbee 回调函数后运行 pytest tests/test_callbacks.py

NEVER: 在没有 Pydantic 验证的情况下直接返回 LLM 原始响应
诊断方法：如果 Claude 反复做你不希望的事，且规则已在 CLAUDE.md 中，通常不是 Claude 不理解，而是文件太长导致规则被淹没。先精简文件，再考虑是否改成 Hook。
07

Session 反思更新

每次 session 结束时，向 Claude 提问：

"What did you learn during this session
that should be recorded for future reference?"

然后将输出分类保存到对应位置，逐步将项目经验沉淀为 AI 可读知识：

内容类型保存位置
通用项目知识、数据模型CLAUDE.md
编码规范、最佳实践.claude/rules/
领域技术能力.claude/skills/
架构决策记录docs/ADR/

这是将工程经验复利积累的核心习惯——越积累，Claude 对项目的理解越深，越少需要重复解释背景。
