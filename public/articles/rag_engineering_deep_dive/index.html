1. RAG 的本质

RAG（Retrieval-Augmented Generation）可以理解为：检索系统 + 生成系统 + 工程治理。文章中把 RAG 解释为“检索系统 + 生成系统”，这是非常准确的工程视角。真正落地时，RAG 不是简单把文档塞进向量库，而是要解决“数据如何处理、如何召回、如何过滤、如何排序、如何让模型只基于证据回答”的完整链路。

1. 文档接入PDF / HTML / Markdown
2. 清洗切片Chunk + 元数据
3. 建索引BM25 + Vector
4. 检索重排TopK + Rerank
5. 生成回答Grounded Answer
面试表达：RAG 的核心不是“能不能跑通 Demo”，而是能否在召回率、准确率、延迟、成本、权限和可观测性之间做权衡。

2. 数据处理链路：ETL 与 Chunking

2.1 文档解析

不同数据源需要不同解析策略：

数据类型处理重点常见问题
PDF页码、标题、段落、表格、图片 OCR多栏排版、页眉页脚噪音、表格结构丢失
HTMLDOM 层级、正文抽取、链接保留导航栏、广告、脚本内容污染
Markdown标题层级、代码块、列表结构切片时破坏标题上下文
业务数据库字段语义、主外键关系、时间版本只向量化文本而忽略结构化过滤条件

2.2 Chunk 大小怎么选

文章提到 512、1024 token 以及 10%–20% overlap。可以这样细化：

场景建议 chunkoverlap原因
FAQ / 短知识100–300 tokens0–10%问题答案短，过大反而引入噪音
技术文档400–800 tokens10%–20%需要保留段落上下文
法律 / 合同800–1500 tokens15%–25%条款依赖上下文，不能切太碎
代码仓库按函数 / 类 / 文件切按依赖关系补上下文固定长度不适合代码语义
推荐的 Chunk 元数据
  • doc_id：文档唯一标识
  • source：来源系统，例如知识库、S3、Git、数据库
  • title_path：标题路径，例如“产品手册 / 计费 / 退款规则”
  • page_no：PDF 页码
  • updated_at：最后更新时间
  • permission_scope：权限范围
  • chunk_index：切片序号
  • hash：内容哈希，用于增量更新

3. 检索：BM25、向量检索与 Hybrid Search

文章中提到 Hybrid Search：BM25 负责关键词精确匹配，Embedding 负责语义匹配。生产系统一般不会只用一种检索方式。

BM25

适合专有名词、错误码、字段名、API 名称、订单号等强关键词场景。

Vector Search

适合同义表达、自然语言问题、概念性检索。

Hybrid Search

两路召回后做结果融合，通常比单一路径更稳。

3.1 RRF 倒数排名融合

RRF（Reciprocal Rank Fusion）常用于融合 BM25 和向量检索结果。它不直接依赖原始分数，而根据排名计算融合分。

score(d) = Σ 1 / (k + rank_i(d))

其中：
- d：文档
- rank_i(d)：文档在第 i 个检索器中的排名
- k：平滑常数，常用 60

3.2 Pre-filter 与 Post-filter

方式含义适用场景
Pre-filter检索前先按元数据过滤权限、时间、业务类型、租户隔离
Post-filter召回后再过滤过滤条件不容易下推到索引时
生产重点：权限过滤必须尽量做 Pre-filter，不能先把无权限内容召回给模型再依赖 prompt 约束。

4. 向量索引：IVF_FLAT 与 HNSW

索引核心思想优点缺点适合场景
FLAT暴力精确搜索召回最准确慢、成本高小规模数据、评估基线
IVF_FLAT先聚类，再在相近簇内搜索速度快，内存可控召回受 nprobe 影响大规模向量检索
HNSW分层图近邻搜索低延迟、高召回内存占用高，构建成本高低延迟在线检索

调参时通常关注：

  • top_k：召回候选数量
  • nprobe：IVF 搜索多少个簇
  • efSearch：HNSW 搜索广度
  • M：HNSW 图连接数

5. Rerank：为什么“召回 100 条，精排 5 条”

文章提到 Bi-Encoder 和 Cross-Encoder 的区别。可以这样理解：

模型方式速度精度用途
Bi-Encoderquery 和 doc 分别编码，再算相似度快中等第一阶段召回
Cross-Encoderquery + doc 拼接后整体判断相关性慢高第二阶段重排序

推荐流程：

BM25 Top50
Vector Top50
      ↓
RRF 融合，得到 Top100
      ↓
Cross-Encoder Rerank
      ↓
取 Top5 / Top8 进入 Prompt

6. 生成阶段：Grounded Answer

RAG 的生成阶段必须约束模型基于资料回答，而不是自由发挥。

你是企业知识库助手。
请严格依据【参考资料】回答。
如果资料中没有答案，请回答“根据当前资料无法确认”。
回答时给出引用来源，包括文档名、页码或标题路径。
  • 要求模型引用来源
  • 禁止使用未提供的背景知识补充关键结论
  • 对证据不足的问题返回“不确定”
  • 将答案结构化输出，便于前端展示

7. RAG 评估指标

指标含义如何优化
Recall@K正确答案是否进入 TopK优化 chunk、embedding、hybrid search
MRR正确文档排名是否靠前加入 rerank
Faithfulness答案是否忠于资料改 prompt、引用校验
Latency端到端耗时缓存、并发检索、模型裁剪
CostEmbedding、Rerank、LLM 成本增量索引、缓存、减少上下文

8. Go 在 RAG 中适合做什么

  • 文档上传与解析服务：Gin / Fiber + 异步任务队列。
  • 索引构建管道：批量 embedding、失败重试、增量更新。
  • 检索 API：并发调用 BM25、向量库、reranker。
  • 流式回答：SSE / WebSocket + context cancellation。
  • 权限控制：租户、用户、部门、文档 ACL 下推到检索层。
