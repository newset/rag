Architecture Comparison

RAG 架构
全景对比

六种主流检索增强生成架构的能力边界、工程权衡与适用场景

架构详解
⬡
向量数据库 RAG
文档 Embedding 后存入向量库，用余弦 / ANN 语义相似度检索 Top-K 片段
语义搜索 大规模文档 低延迟
优势
同义 / 近义表达均可召回，语义理解强
ANN 索引毫秒级返回，延迟低
支持亿级 chunk 规模
离线可用，不依赖外部服务
劣势
知识有时效性，更新需重新索引
精确 ID / 数字召回弱
多跳推理能力差
领域外 Embedding 质量下降
文档 → Embed → 向量库 → 查询向量 → Top-K ANN → LLM → 回答
适合 /  研报问答 策略知识库 客服 FAQ 代码语义搜索
⚙
MCP RAG
LLM 通过 Model Context Protocol 工具调用实时获取外部数据，支持读写操作
实时数据 可写操作 结构化查询
优势
直连数据源，数据永远最新
支持写入、触发操作，不只是读
精确条件过滤与聚合计算
无需维护向量索引
劣势
语义模糊查询能力弱
延迟高，依赖工具可用性
每个数据源需开发 MCP 接口
权限管理复杂度高
提问 → LLM 选择工具 → MCP Tool → 数据源 → 结果 → LLM → 回答
适合 /  行情查询 实时持仓 日历操作 CRM 写入
◈
图谱 RAG（GraphRAG）
将文档解析为知识图谱（实体＋关系），通过图遍历做多跳推理和关联检索
多跳推理 关系检索 结构化知识
优势
擅长多跳推理（A→B→C 关系链）
实体关系查询准确，不靠语义相似
全局摘要能力强，跨文档关联
适合医疗、法律等知识密集型领域
劣势
图谱构建成本高，需 NER + 关系抽取
非结构化文本转图谱质量参差不齐
维护更新复杂，存在图谱腐烂问题
工程难度高，工具链不成熟
文档 → NER+关系抽取 → 图谱 → 图遍历/Cypher → 子图 → LLM → 回答
适合 /  医药知识库 法律条文推理 供应链关联分析
⊞
SQL RAG（Text-to-SQL）
LLM 将自然语言转为 SQL，直接查询结构化数据库，返回精确数据
精确查询 结构化数据 聚合分析
优势
精确数值、聚合、排名查询无敌
数据实时，无需建索引
结果可解释，SQL 可审计
已有 DB 直接复用，零新存储成本
劣势
SQL 生成可能出错，需验证层
只适用于结构化数据，文本检索弱
复杂 JOIN / 子查询生成质量不稳
暴露 schema 带来安全风险
提问 → LLM 生成 SQL → 执行引擎 → 结果集 → LLM 格式化 → 回答
适合 /  量化数据分析 财务报表 持仓 P&L 统计 BI 自然语言
⊕
混合检索 RAG（Hybrid RAG）
稠密向量检索（语义）与稀疏检索（BM25 关键词）融合，互补召回后 Rerank
语义+关键词 Reranker 召回率高
优势
召回率远高于单一方式
关键词精确匹配 + 语义模糊双保险
Reranker 提升精排质量
当前生产环境最常用方案
劣势
架构复杂，需维护两套索引
两路并行 + 重排延迟略高
融合权重调优需经验
仍不擅长多跳推理和实时数据
查询 → Dense+Sparse 并行 → RRF 融合 → Reranker → LLM → 回答
适合 /  企业知识库 技术文档搜索 电商商品检索
✦
Agentic RAG
Agent 自主规划检索策略，动态决定调用哪些工具、迭代几轮，支持复杂多步推理
自主规划 多工具编排 迭代推理
优势
能处理上述所有架构解决不了的复杂问题
动态选择最优检索路径，自适应
可迭代验证、自我纠错
是以上所有架构的编排层
劣势
延迟最高，多轮工具调用叠加
成本高，Token 消耗大
行为不可预测，调试难度高
需要强大 LLM，弱模型乱规划
提问 → Agent 规划 → 选工具(向量/SQL/MCP/图谱…) → 执行 → 评估 → 迭代 → 汇总
适合 /  多源复杂分析 AI 研究助手 交易策略生成

选型决策参考
根据核心需求选架构
需要语义搜索大量文档？
→ 向量 RAG
需要操作实时数据或写入？
→ MCP RAG
需要多跳关系推理？
→ 图谱 RAG
需要精确统计聚合分析？
→ SQL RAG
追求最高召回率？
→ 混合检索
需要处理跨源复杂问题？
→ Agentic RAG
交易平台最优实践
向量 RAG（策略文档）＋ MCP RAG（实时行情/持仓）＋ SQL RAG（历史统计）→ Agentic 编排
